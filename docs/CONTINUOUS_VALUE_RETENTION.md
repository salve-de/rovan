# Rovan 継続価値・リテンション設計

> Rovanを一回の診断で終わらせず、公開事実の更新を実行し、同じ条件で再測定・報告するサービスの製品目標。実装・本番の成立は別途検証する。
>
> 最終更新: 2026-09-22

## 0. 結論

月額で提供するのは、Rovan上で許可された公開情報の改善を実行し、外部顧客サイトについては実装直前まで完成したChange Packを自動生成し、その後のAI回答を測定して次の対応まで続けること。自社サイトへの直接書き込みは行わず、利用者と運営者の手間を極限まで減らし、大手と正面から競わずに実在するニッチな強みで推薦候補を取り戻すことを目指す。

```text
Before → Rovanが何を更新したか → After（同条件の再測定）→ 次に何をするか
```

初回の明示同意の範囲で公開事実の更新・再測定・報告を自動継続する。毎週の確認案だけを渡して顧客に実行させる形を完成形にしない。変更なしや改善しなかった場合も正直に示す。推薦・顧客獲得・売上を保証せず、解約困難化ではなく継続した実行と検証を対価にする。

## 1. 北極星指標

北極星は **AI顧客奪還シェア（Competitor Take-Back Share）**。買い手を想定した固定代表50問パネルに対し、自社が推薦候補枠に入った質問の割合と、その導入前後・継続測定での推移を追う。競合候補との関係は回答ログで併記する。これは測定パネル上の観測であり、実際の顧客数・顧客シェア・売上・全利用者の会話・AI内部順位ではない。

算出は「自社の候補入りを確認した質問数 ÷ 取得に成功した固定パネル質問数」。全50問取得時の分母は50。欠損時は成功分母・予定50問・未取得数を併記し、部分観測として完全パネルと区別する。前後比較は両時点で比較可能な質問に揃え、その分母を示す。分母0や条件不一致は比較不可とする。質問・パネル版・AI面・Provider・モデル・地域・言語・反復条件と各測定日時を保存し、Provider別に表示する。反復の判定規則は事前に固定する。候補入りは競合の脱落や第一候補化を意味しない。第一候補への変化は回答ログで別途確認する。

初回候補外質問だけを分母にする「候補回復率」は補助指標であり、北極星の名称・分母を置き換えない。無料の短いパネルを50問の結果として表示せず、パネル移行時は基準測定を取り直す。改善だけでなく、低下・変化なし・欠損も示し、施策による因果効果や将来の推薦成果を保証しない。

## 2. 継続測定で確認する項目

毎回、数値だけでなく母数と条件を並べる。

| 項目 | 表示内容 |
| --- | --- |
| 質問パネル | パネル種別、バージョン、質問数 |
| 観測条件 | AI提供元、モデル、地域、測定日時、反復回数 |
| 取得状態 | 予定数、成功数、未取得数 |
| 候補入り | 自社が回答に含まれた質問数・割合 |
| 参照元 | AI回答から取得できたURLと質問との対応 |
| 変更 | 前回との差分。差分がない場合も「変化なし」と明示 |
| 実施内容・次の対応 | 公開した事実・差分・参照元・実行結果と次の自動対応。範囲外は保留理由 |

取得できなかった回答は候補外として数えない。成功した回答だけを母数にした場合は、そのことを画面と書き出しデータに残す。

## 3. 提供する価値のループ

```text
Measure
  → Explain
  → Select source-backed niche facts
  → Generate implementation-ready Change Pack
  → Publish only on opted-in Rovan surfaces
  → Remeasure
  → Record uncertainty
```

### 3.1 Measure

固定した質問パネルでAI回答を取得し、回答本文・候補文字列・参照元URL・提供元・モデル・測定日時を保存する。

### 3.2 Explain

自社が候補に含まれたか、候補外だった質問、回答に含まれた他社候補、引用された公開ページを確認できるようにする。候補名は回答ログ上の文字列であり、他社の品質評価ではない。

### 3.3 実在するニッチ事実を選ぶ

公開情報から確認できる事実と未確認項目を分ける。競合の規模や即日対応を模倣させず、自社の地域、専門分野、自社施工など出典で確かめた強みを整理する。観測データの蓄積は改善候補の選定に使い、秘密情報や非公開ログを他社の公開ページへ転用しない。

### 3.4 初回同意の範囲内で公開更新する

初回に、対象企業・Rovan上の公開先・参照元・更新する事実項目と操作範囲を示し、公開と継続自動更新への明示的なオプトインを得る。その同意の範囲内で、参照元付きの客観的事実の追加・更新・失効、再測定、報告を自動で続けることを製品目標とする。通常の週次更新に毎回の承認を要求しない。対象や公開先の変更、範囲外の内容、権利・根拠が未確認の内容は保留し、必要な範囲だけ追加確認する。同意撤回・停止・訂正・非公開の導線と、同意範囲、原典、公開差分、実行日時、失敗・復旧の記録を持つ。取得失敗だけで事実を削除せず、原典での失効と区別する。

対象会社のサイト、CMS、DNS、広告、CRM、第三者サイト、AI Provider内部データは変更しない。自由文のChange Packや範囲外の編集は下書きに留める。一方、外部サイトを変更しないことを理由に助言だけで止めず、対象URL、変更位置、完成文、FAQ、比較表、title/description、JSON-LD、内部リンク案、対象Buyer Prompt、検証チェック、再測定条件まで可能な限り自動生成する。

### 3.5 Remeasure

変更後は、質問・AI・地域・反復条件を揃えて再測定する。条件が変わった場合は、前回との比較を成立させない。

### 3.6 Record uncertainty

観測された時間的な変化と、変更が原因であるという因果判断を分離する。外部サイト、検索結果、モデル更新、質問文の差を確認できるようにする。

## 4. Watch画面の情報設計

ダッシュボードの優先順位は次の順にする。

1. **今回の状態** — 自社の候補入り率、取得成功数、測定日時。
2. **前回との差分** — 候補入り・候補外・参照元URLの変化。
3. **比較条件** — パネル、質問数、AI、モデル、地域、反復回数。
4. **根拠** — 対象質問、回答ログ、参照元URL。
5. **実施内容・次の対応** — 公開更新の差分・参照元・結果と次の自動対応。例外は保留理由を示す。

大きな数字を単独で見せない。数字の直下に母数・条件・注記を置き、カードを増やすより同じ定義の表と差分にまとめる。

## 5. 変化の状態

| 状態 | 意味 |
| --- | --- |
| 改善 | 同じ比較条件で、自社が候補に含まれた質問を確認 |
| 低下 | 同じ比較条件で、自社が候補外になった質問を確認 |
| 条件変更 | パネル、AI、モデル、地域、反復条件が一致せず比較不可 |
| 取得不足 | 一部または全部のAI回答を取得できず、確定できない |
| 変化なし | 比較可能な条件で前回との差分を確認できない |

「改善」「低下」は観測上のラベルであり、顧客行動や売上の変化を意味しない。

## 6. 競合・参照元の扱い

AI回答に含まれた他社候補は、今回の質問に対する比較対象として表示する。競合サイトの本文差分を検知した証拠が保存されていない場合、「競合サイトが変更された」とは表示しない。

06221ca時点の文書は、競合Webの前後クロール差分を永続化していないと記録していた（今回コード・本番は未検証）。その場合、競合Web変更イベントは生成しない。AI回答内の候補増減と、競合サイト本文の変更は別のデータとして追加するまで混同しない。

## 7. Activityと通知

通知に載せるのは、実際に保存された観測・差分・参照元・公開更新結果・保留理由だけとする。作業量を示す架空の件数や、確認していない競合巡回件数を表示しない。

通知の最小構成は次のとおり。

- 対象と測定日時
- パネルと取得成功数
- 自社が候補に含まれた質問数
- 候補外として記録された質問数
- 参照元URLの追加・削除
- 比較不可または取得不足の理由
- Rovanが自動更新した事実・公開URL・実行日時（実施済みの場合）
- 次の自動対応、範囲外の保留理由（必要な場合だけ追加確認）
- 結果画面へのリンク

無料期間や課金条件は料金ページ・特商法表記・決済画面と同じ値を使う。

## 8. データ境界

| 保存するもの | 公開してよいもの | 公開しないもの |
| --- | --- | --- |
| 回答ログ、参照元、条件、差分 | 承認済み事実、参照元、更新日時 | 未承認の回答ログ、他社名を含む測定ログ、Evidence、メール、トークン |
| Change Pack、確認項目 | 確認済みの公開プロフィール | 原価、秘密値、Provider内部情報 |
| Watch履歴、取得状態 | 公開範囲を明示した要約 | 顧客・売上・市場シェアへの換算 |

## 9. 修正前の実装記録と製品目標の距離

以下は06221ca時点の文書記録を引き継いだもの。今回コード・本番の稼働は再検証しておらず、並行する実装作業との照合が必要である。

| 現行実装 | 扱い |
| --- | --- |
| 無料診断 | 固定した無料質問パネルで一度観測。未取得は欠損として扱う |
| 有料Watch | 固定コアパネルを同じ条件で再測定し、履歴と差分を保存 |
| Change Pack | 取得済み公開ページと確認済み入力を素材にした承認前ドラフト |
| 自動対応 | 修正前文書では原文スニペットの確認案まで。初回同意の範囲内の公開更新・再測定・報告までが製品目標であり、実装と運用証拠が必要 |
| 競合Web変更 | 永続クロール差分がないため判定しない |
| AI顧客奪還シェア | 固定代表50問の比較可能な観測で定義を揃える。候補回復率は別の補助指標。コード・本番の算出は要照合 |

## 10. 成功条件

利用者が毎回、次を答えられること。

1. 今回どの条件で測定したか。
2. 何件の回答を取得できたか。
3. どの質問で自社が候補に含まれたか。
4. 前回から何が変わったか。
5. どのURLが根拠になったか。
6. Rovanが何を公開更新し、次に何を自動で行うか。
7. 外部サイトで実施すべき変更がある場合、どこに何を入れるか完成形で分かるか。\n8. 何がまだ分からないか。

完了の証拠として、初回同意後の週次公開更新、再測定、通知、同意撤回後の停止、失敗時の保留・復旧を実環境で確認する。単なる診断結果だけでは継続価値の完成としない。観測値を実際の市場シェアや顧客奪還数へ換算しない。
